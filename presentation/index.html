ОБЪЕКТЫ STUDIO

Run, thread и assistant не одно и то же

Assistant

Какой граф и с какой конфигурацией запускать

В нашем проекте выбор начинается с weather_agent или web_search_agent.

Thread

Контейнер одной продолжающейся истории

Связывает несколько запусков и их checkpoints.

Run

Одна конкретная попытка выполнить граф

Новый запрос в том же thread создаёт новый run.

Assistant выбирает поведение, thread хранит продолжение, run выполняет шаг

State показывает, что граф знает сейчас

MessagesState

Готовая схема с одним каналом messages и reducer add_messages.

  ]
}

Node читает state и возвращает только обновление нужных полей

CHECKPOINTER

Локально память подключается при compile

from langgraph.checkpoint.memory import InMemorySaver

checkpointer = InMemorySaver()
graph = workflow.compile(
    checkpointer=checkpointer
)

config = {
    "configurable": {
        "thread_id": "kfu-17"
    }
}

graph.invoke(input, config)

Checkpoint

Снимок state на шаге выполнения. Он поддерживает продолжение разговора, восстановление после сбоя и time travel.

В Agent Server: инфраструктура persistence подключается автоматически.

InMemorySaver удобен для обучения, но теряет данные после перезапуска процесса

MEMORY DESIGN

Хорошая память начинается с правил данных

01

Сохранять выборочно

Не весь разговор, а полезные факты с понятной схемой.

02

Разделять scope

Диалог в thread, устойчивые предпочтения в Store.

03

Возвращать по необходимости

Подмешивать только релевантные записи, а не весь архив.

04

Уметь исправлять и удалять

Источник, дата, версия, TTL и явная команда забыть.

Память является продуктовой политикой, а не побочным эффектом чата
